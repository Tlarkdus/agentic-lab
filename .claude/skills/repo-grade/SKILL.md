# repo-grade

저장소가 "에이전트가 일하기 좋은 상태"인지 채점한다. 추측 금지 — 모든 점수는 실제로 읽은 파일이나 돌린 명령의 결과로만 준다.

## 절차

1. 구조 파악: `git ls-files`, 루트 파일 목록, `package.json`
2. 규칙 문서 읽기: `CLAUDE.md`, `GOLDEN_RULES.md`, `docs/`, 폴더별 `.agent-rules.md`
3. 대조: 문서가 지목한 경로가 실재하는지, 금지 조항이 실제 코드와 어긋나지 않는지 `grep`으로 확인
4. 게이트 실행: `npm test` (없거나 실패하면 그 사실이 근거)
5. 루브릭으로 채점 → 아래 출력 형식으로 보고

## 루브릭 (5 × 20점 = 100점)

| 카테고리 | 0점 | 10점 | 20점 |
|---|---|---|---|
| **A. 길 안내** — 진입점·핵심 파일 안내 | 어디부터 볼지 알려주는 문서가 없다 | 구조 설명은 있으나 실재하지 않는 경로가 섞여 있거나 핵심 파일이 빠져 있다 | 진입점·활성 코드·로거·테스트 위치가 명시되고 전부 실재한다 |
| **B. 규칙 문서 품질** — CLAUDE.md | CLAUDE.md가 없다 | 있으나 35줄 초과로 장황하거나, 명령어·금지사항 중 한쪽이 빠져 있다 | 35줄 이내로 간결하고 실행 명령어와 금지사항이 모두 있다 |
| **C. 숨은 규칙 문서화** — Why·Gotcha | 규칙만 있고 이유가 없다 | 일부 조항에 이유가 붙어 있다 | 함정(동명이인 죽은 코드, 계산 순서, 실패 처리 방식 등)이 이유와 함께 기록돼 있다 |
| **D. 검증 게이트** — 테스트 | 테스트가 없다 | 테스트는 있으나 실행 방법이 문서에 없거나 실패한다 | `npm test`로 돌아가고 통과하며, 문서가 이를 완료 기준으로 지정한다 |
| **E. 신선도** — 문서 ↔ 코드 일치 | 문서가 코드와 정면으로 어긋난다 | 사소한 표류가 있다 (누락된 파일, 낡은 필드 목록) | 대조한 모든 조항이 현재 코드와 일치한다 |

경계 판단은 낮은 쪽으로 준다. 10점과 20점 사이에서 고민되면 10점.

## 출력 형식

| 카테고리 | 점수 | 근거 | 개선 제안 |
|---|---|---|---|

근거 칸에는 파일명·줄번호나 명령 결과를 적는다 ("좋음" 같은 평가어 금지).

**총점: NN / 100**

**ROI 순 개선 3가지** — 적은 노력으로 큰 점수를 얻는 순서. 각 한 줄: `[+N점] 무엇을 / 어디에`

## 금지

- 채점만 한다. 파일을 고치지 않는다. 수정은 사용자가 요청하면 그때.
- 돌려보지 않은 명령의 결과를 근거로 쓰지 않는다.
